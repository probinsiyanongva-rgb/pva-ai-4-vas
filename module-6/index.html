Choosing the Right AI Tool

By now you've used AI for communication, research, and operations. This module steps back and asks a different question: which AI tool should you use, and why? The purpose is not three separate tool tutorials — it's tool judgment that outlasts any one tool's current feature set.

As before, picking an answer in a practice exercise marks it done in your progress — it isn't graded. The goal is judgment, not a score.

6.1 VA Skill: Basic tool awareness

The Core Three

Big Question What should you know about ChatGPT, Gemini, and Claude before deciding which one to use?

1. Why This Module Exists

You've already used AI for communication, research, summaries, documentation, checklists, reports, spreadsheets, and operational work. Now we step back and ask: which AI tool should I use for a particular task? The purpose is not to teach three separate AI courses — it's to teach tool judgment. The core tools in this course are ChatGPT, Google Gemini, and Claude. Their capabilities can overlap significantly, so the goal is not to memorize "ChatGPT is for X" or "Claude is always better for Y" — those statements can become outdated. Instead, learn to look at the task and then evaluate the tools available to you.

2. Think of the Tools as Work Tools

You don't need to become a fan of one tool. Think of AI tools the way you might think about a preferred spreadsheet application or writing environment — if a client requires another system, you work with the system that fits the job.

3. What to Notice

When looking at an AI tool, pay attention to: Input (what can you give it — text, documents, images, structured information?), Output (what can it help produce — drafts, summaries, tables, analysis?), Current Information (does the task need information that needs to be current?), Documents and Context (how well does it support the amount of information you need?), Workspace or Integrations (does the task involve another environment or service?), and Refinement (how easy is it to review and continue working with the result?).

4. Tool Strengths Are Not Permanent

A tool can gain a new capability. Another can improve an existing feature. Pricing, access, limits, interfaces, and available features can all change. The habit to build: check the current capability when the capability matters to the task. Do not memorize rankings.

5. A Practical Comparison

ToolWhat to Examine
ChatGPTCurrent writing, analysis, document, research, and workspace capabilities available to you
Google GeminiCurrent capabilities, especially where the task benefits from Google's ecosystem or available integrations
ClaudeCurrent writing, analysis, document, and long-context capabilities available to you

These are starting points for evaluation, not permanent rankings. Exact capabilities depend on account type, plan, interface, and current product changes.

6. Demonstration: How to Evaluate a Tool

"I have a long set of onboarding notes. I need a concise internal summary with decisions, action items, and open questions."

Don't immediately say "I'll use my favorite AI tool." Instead ask: what is the task (summarization and organization)? what is the input (a long document)? what is the output (a concise structured summary)? what matters (document handling, context, accuracy, structure, ease of refinement)? Now compare the current versions of the tools based on those requirements. That is tool judgment.

6.2 VA Skill: Comparative evaluation

Same Task, Three Tools

Big Question What happens when you give the same VA task to ChatGPT, Gemini, and Claude?

1. Why Compare the Same Task?

If you give different tasks to different tools, you can't easily tell whether a difference came from the tool, the task, the instructions, the source material, or how you used it. A controlled comparison helps: same task, same source material, same basic instruction, three tools. This is one of the few places in the course where a direct three-tool comparison is deliberately useful.

2. What Are We Comparing?

Don't compare based on "which answer do I like?" Use consistent criteria: Usefulness (did it actually help?), Accuracy (did it preserve the source correctly?), Structure (organized usefully?), Tone (appropriate for the audience?), Ease of Refinement (could you easily improve it?), Verification Needs (how much checking was required?).

3. Controlled BrightPath Task

BrightPath is reviewing its onboarding process. Students receive a welcome email after enrollment. The onboarding sequence includes orientation information and links to the student help resources. During the latest review, Sarah asked the team to identify which onboarding items are complete, which still need review, and which questions need clarification. Daniel has reviewed the current onboarding copy. Maya is checking the help-resource links. One question about the orientation content still needs Sarah's decision.

Sarah asks: "Create a concise internal summary with three sections: Completed, Still in Review, and Needs Decision."

4. Standardize the Test

Use the same source material, task, output requirements, audience, and basic instruction. Run the task through ChatGPT, Google Gemini, and Claude. Don't change the task simply because the first tool gives an answer you prefer.

5. Compare the Results

6. Do Not Confuse "Best" With "Best for This Task"

Tool A produced the clearest structure. Tool B produced more concise wording. Tool C required the least editing. There doesn't have to be one permanent winner. "For this task, Tool A gave me the most useful structure, although I still needed to verify the status details" is much more useful than "Tool A is the best AI."

7. PRACTICE: Find the Difference LEARNING ARTIFACT

Source: "Maya is checking the help-resource links." One tool writes: "Maya is reviewing the help-resource links" — a reasonable wording change. Another writes: "Maya completed the help-resource review" — that changes the status.

The second output requires correction — it changed what's actually true. This is why comparative evaluation still includes verification, no matter how well a tool performs on style.

8. PRACTICE: Refinement

Tool A produces a correct summary but uses long paragraphs. Tool B produces bullet points but omits the unresolved orientation decision. Tool C is concise but changes "still needs Sarah's decision" to "Sarah approved the update." Which is automatically best?

None. Each has a different issue. The VA should compare the actual work, not simply choose based on style.

Complete the same BrightPath task in ChatGPT, Google Gemini, and Claude.

11. AI Audit Note

12. Reflection

13. Lesson Close

Using multiple AI tools does not mean using all three for every client task. This comparison has a specific purpose: learn how to evaluate tools instead of assuming one tool will always win. In the next lessons, you'll use that judgment to choose the tool that fits the job.

6.3 VA Skill: Tool evaluation

Tool Strengths Change

Big Question How do you know whether an AI tool is actually a good fit today?

1. AI Tools Do Not Stay the Same

"ChatGPT is always best for writing." "Claude is always better for long documents." "Gemini is the best choice if the client uses Google." These statements may sound useful — they're also too absolute. AI tools change: features are added and improved, interfaces change, some capabilities become available only on certain plans. A tool that was especially useful six months ago may no longer have the same advantage today. A good VA learns how to evaluate a tool, not just what someone once said about it.

2. Your Knowledge About a Tool Has an Expiration Date

Durable Knowledge (likely to stay useful): compare the tool with the task, check what information it can work with, consider the required output, consider privacy, check whether current information is needed, test the result, verify important information.

Temporary Knowledge (can change): which tool has a particular feature, which interface supports a particular workflow, which plan includes a capability, which tool handles a particular file type best, which tool produces better results today, which integrations are currently available.

3. Do Not Memorize Rankings

A published "three best AI tools" comparison can be useful information — but ask: when was it published? What task was tested? What information was provided? What version or plan was used? What criteria determined "best"? Does the client's actual task match the test? A ranking is not a substitute for task-based judgment.

4. Check Current Capabilities

When a capability matters to the task, check the tool's current official information or test the capability directly. For a long document, you might check: can this tool currently handle it? Is the capability available on my account? Can it work with the format I have? Can it produce the output I need? Are there privacy or client-policy concerns?

5. Test the Capability, Not the Reputation

Instead of "which AI tool is the best?" ask: "which available tool can handle this document, produce the required structure, and give me a result I can verify and improve?" That's a much better VA question.

6. BrightPath Example

Sarah gives you a 70-page internal training document and wants key operational changes, action items, and clarification questions. You remember hearing that "Tool A is the best for long documents." Before choosing it automatically, check: can your current account handle the document? Can the tool work with the format? Can it produce the requested structure? Can you verify the output against the source? Does the client allow this document to be processed by that tool? If the answer to one of these changes, your tool decision may change too — that's professional tool evaluation.

7. PRACTICE: Permanent Rule or Current Observation? LEARNING ARTIFACT

8. PRACTICE: What Would You Check?

Sarah asks you to use AI to analyze a large client document. Before selecting a tool, identify five things you'd check (document handling, current availability, output requirements, privacy, client preference, current information needs, ease of verification — choose what actually matters).

9. PRACTICE: The Old Recommendation

A VA tells you: "Use Claude. It's always the best for long documents." Your response shouldn't simply be "that's wrong" — explain what the VA should check before making that recommendation.

10. PROVE: Updated Current Tool Capability Snapshot PROOF-OF-SKILL ARTIFACT

Revisit the snapshot from Lesson 6.1 — what has changed since you checked? Focus only on capabilities you can reasonably verify; don't create a long feature list.

ImportantThis is a learning exercise, not durable portfolio evidence. Its purpose is to teach you that AI capabilities change and tool selection should be based on current task requirements rather than permanent rankings. Your snapshot may become outdated — that's part of the lesson.

11. Human Judgment Checkpoint

Which parts of my snapshot are current observations rather than permanent facts? What would I need to check again before using this for a future client task? Did I evaluate capabilities based on actual task needs or just compare feature lists?

12. Reflection

13. Lesson Close

You don't need to memorize everything each AI tool can do. You need to know how to find out what matters when the task requires it. That's a much more durable skill.

6.4 VA Skill: Tool selection

Choosing a Tool for the Job

Big Question How do you choose the right AI tool for a real client task?

1. Start With the Task

Don't begin with "which AI tool should I use?" Begin with "what am I actually trying to accomplish?" A short email requires different capabilities from a long-document review, spreadsheet analysis, current-information research, a Google Workspace workflow, or a sensitive client task.

2. Look at the Input

What information does the tool need to work with — short text, a long document, several documents, a spreadsheet, structured data, an image, information requiring current research? The tool needs to be able to handle the type and amount of information involved.

3. Look at the Output

What does the final result need to look like — a short email, a table, a summary, a research brief, a formula explanation, structured notes, a draft to be edited manually? A tool that can process the input isn't automatically the best choice if it can't support the output workflow you need.

4. Consider Current Information

Some tasks need information that may have changed recently — current product info, company info, schedules, policies, market information. If current information matters, consider whether the tool and workflow can appropriately access it. And remember: access to current information does not automatically make the output correct — important information still needs verification.

5. Consider Integrations

Sometimes the surrounding workflow matters — documents, email, calendars, spreadsheets, shared files. But an integration is only valuable if it actually helps complete the task. Don't choose a tool simply because it has more integrations.

6. Consider Client Preference

"Our team uses Gemini for internal work. Please use that unless there is a reason not to." If the client's chosen tool can handle the task appropriately, using it may be the most practical choice. You should also know when to raise a concern — if the tool can't safely or effectively perform the task, communicate that rather than forcing the work through it.

7. Consider Privacy

A tool decision is incomplete if you ignore information sensitivity. What information am I handling? Am I allowed to use this tool with it? Does the client have a policy? Can I complete this task another way? Tool selection and information protection are connected.

8. A Simple Tool Decision Process

1. Task

What am I trying to do?

2. Input

What information will the tool need?

3. Output

What result do I need?

4. Requirements

Current info, long documents, integrations, other capabilities?

5. Constraints

Client preferences or privacy requirements?

6. Current Capability

Which available tool currently fits?

7. Verification

Can I check and verify the result?

Then choose.

13. Human Judgment Checkpoint

If the client asked why you chose this tool, could you explain the decision using the task requirements rather than personal preference? If the tool produced a poor result, would you be willing to change tools? If the answer is no, you may be treating tool preference as more important than the task.

14. Reflection

15. Lesson Close

Choosing an AI tool is part of the VA's job. The goal is not to know which tool wins every comparison — it's to recognize what the task requires and choose accordingly.

6.5 VA Skill: Professional tool judgment

Don't Become a Tool Fan

Big Question What do you do when your favorite AI tool is not the right tool for the job?

1. Tool Preference vs. Tool Judgment

You may eventually have a favorite AI tool — that's fine. The problem starts when your preference becomes your decision-making rule. A professional VA asks "what does this task require?" before asking "which tool do I usually use?"

2. Three Different Reasons Not to Use Your Favorite Tool

1. Another AI tool fits better

The task may require a capability your usual tool currently handles less effectively.

2. A simpler tool is better

Faster and clearer with a spreadsheet, standard template, search engine, calendar, manual checklist, or simple copy and paste.

3. AI should not be used

Because of privacy, client policy, sensitivity, accountability, risk, or the nature of the decision.

These are different judgments and should not be collapsed into one general rule.

3. PRACTICE: Practice Scenarios LEARNING ARTIFACT

For each situation, choose: Use your usual AI tool / Switch AI tools / Use the client's required AI tool / Use another non-AI tool / Do not use AI. Explain what the task requires, what makes your approach appropriate, and what you'd verify before proceeding.

Scenario A
You need to organize 40 short customer comments into a few categories.
Scenario B
You need to copy three customer names from one approved list into another spreadsheet.
Scenario C
You have a long client document that your usual AI tool is struggling to process accurately.
Scenario D
The client provides credentials and asks you to paste them into an AI tool to help troubleshoot an account.
Being asked is not the same as it being safeThe client handing you the credentials and asking for this doesn't settle the question — the client authorizing a task is not the same as the client having thought through what's safe to put into an AI tool. That judgment is still yours to make. This is the same principle from Lesson 1.4: use only the minimum information the task actually needs, and credentials specifically should stay out of the AI workflow entirely, request or no request.
Scenario E
The client specifically requires work to be completed using a particular AI tool — one that may or may not be the tool you'd normally reach for.

Scenario E has its own answer, separate from the other four: if the client's required tool can handle the task appropriately, using it is usually the right call, even if it's not your usual choice — that's respecting client preference, one of the factors from Lesson 6.4. The judgment is in checking that the required tool can actually do the job, not in resisting it.

4. Deliberate Risk

BrightPath needs a simple way to collect recurring questions from a small internal team. The proposed solution is a complex AI-powered knowledge system with multiple automated steps, classification rules, and integrations. Is that level of complexity justified? The better answer may be a structured form, a shared spreadsheet, a categorized document, or a standard response template.

The real questionNot "Can AI do this?" but "Is AI actually the best way to solve this problem?"

5. PROVE: Final Tool Selection Decision CAPSTONE EVIDENCE

For several scenarios, document: Task, Selected approach, Why it fits, Why another option was not selected, What needs to be verified, What remains the VA's responsibility. The selected approach may be an AI tool, another tool, or no AI.

7. Reflection

8. Client-Ready Standard

Tool neutrality is part of professional judgment A professional AI-assisted VA should be able to say "I chose this approach because it fits the task." They should also be comfortable saying "AI is not necessary for this" or "this AI tool is not the right fit for this task."
